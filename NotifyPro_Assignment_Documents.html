CSS Architecture

I built the CSS from the ground up using a token-driven approach where every colour, spacing, and shadow lives in a CSS custom property. That way, toggling a single class switches the entire theme — no hunting through hundreds of selectors.

Architecture Overview

I split the CSS into three clear layers so it stays easy to maintain and scale — nothing overlaps, nothing fights each other.

Theme Handling

The theme system supports two modes — Light and Dark. It's built on CSS custom properties, so switching themes is just a matter of toggling one class on the <html> element. No duplicate components, no extra CSS.

Three Theme Modes
ModeBehaviourTrigger
LightLight background, dark text — default themeDefault — user selects via topbar toggle
DarkDark OLED-like background, light textUser selects via topbar toggle
Persistence
Your theme choice gets saved to localStorage as ntf-theme and is applied before the page even renders — so there's never that ugly flash of the wrong theme on reload. Default is Light.
Technical Implementation
CSS Token Override Strategy

Components are written once — they just reference tokens. The .dark class on <html> overrides only the tokens that actually change between themes. No component needs to be rewritten or duplicated.

/* Light Theme — :root (default) */ :root { --bg-color: #F8FAFC; --surface: #FFFFFF; --text: #0F172A; --border: rgba(226, 232, 240, 0.8); } /* Dark Theme — .dark on <html> */ .dark { --bg-color: #05050A; /* OLED near-black */ --surface: #0F111A; --text: #F8FAFC; /* Near-white */ --border: rgba(255, 255, 255, 0.06); }
Theme Toggle — JavaScript
function applyTheme(t) { const d = document.documentElement; if (t === 'dark') { d.classList.add('dark'); // CSS cascade does the rest } else { d.classList.remove('dark'); } }

UX Principles

I applied nine core UX principles throughout the design, based on Nielsen's Heuristics and modern interaction patterns. Each principle connects directly to a real feature you can see in the prototype.

Principle 01 — Nielsen Heuristic #1
Visibility of System Status
"Always keep users informed about what is going on, through appropriate feedback within reasonable time."
Toast feedback: Every action — save, schedule, delete, even switching themes — triggers a little toast that slides in from the top-right and fades out after 4 seconds. You always know something happened.

Unread badges: The sidebar shows a live count on "My Inbox" and the topbar bell has a pulsing red dot when there's something new. No need to click around to find out.

Animated counters: Key stats like "28,491 sent" and "1,847 active users" count up from zero when the page loads — makes the data feel alive and draws your eye to what matters.

Progress bars: The Monitoring page uses colour-coded bars so you can see delivery rates at a glance.
Principle 02 — Nielsen Heuristic #2
Match Between System and the Real World
"The system should speak the user's language — words, phrases, and concepts familiar to the user."
Plain language everywhere: It's "My Inbox", not "User Notification Centre". It's "Schedule Campaign", not "Temporal Dispatch Configuration". I kept the labels simple and human.

Familiar inbox layout: The notification centre looks like Gmail or Outlook — sender avatar, subject line, preview text, timestamp. Anyone who's used email can jump right in with zero learning curve.

Colours that make sense: Green means Active, Yellow means Draft, Red means Urgent. These are universal cues that work across cultures.
Principle 03 — Nielsen Heuristic #3
User Control and Freedom
"Users often choose system functions by mistake and will need a clearly marked 'emergency exit'."
Cancel is always an option: Every modal has a Cancel button. You never get stuck in a flow you didn't mean to start.

Escape to freedom: Pressing Escape closes any modal or dropdown from anywhere. No hunting for the close button.

Click outside to dismiss: Clicking the backdrop behind a modal or clicking outside a dropdown closes it. Simple, natural, expected.

Confirm before sending: Hitting "Send Now" always shows a confirmation modal first — one last chance to change your mind before a campaign goes out to thousands.
Principle 04 — Nielsen Heuristic #4
Consistency and Standards
"Users should not have to wonder whether different words, situations, or actions mean the same thing."
One token system to rule them all: Every screen uses the same primary colour, border radius, shadow, and transition. No random one-off values anywhere.

Clear button hierarchy: Primary buttons are filled gradient, secondary are outlined glass, ghost is transparent. This pattern stays the same on every single page.

Consistent card pattern: Dashboard, Templates, Recipients, Monitoring — they all use the same card component. Learn it once, and you know how every part of the app works.
Principle 05 — Nielsen Heuristic #5
Error Prevention
"Even better than good error messages is careful design which prevents problems from occurring."
Live preview as you type: When composing a notification, a preview panel updates in real-time on the right. You see exactly how it'll look before it goes out to thousands of people — catches formatting mistakes early.

Clickable variable chips: Instead of typing {{name}} manually and risking typos, you just click the chip and it's inserted perfectly.

Timezone dropdown: An explicit timezone selector means you won't accidentally schedule a campaign for 3 AM in the recipient's timezone.
Principle 06 — Nielsen Heuristic #6
Recognition Rather Than Recall
"Minimise the user's memory load by making objects, actions, and options visible."
Sidebar always visible: All 8 screens are listed in the sidebar at all times. You never have to remember where something is — it's right there.

Template cards show everything: Name, channel type, category, status, send count — all visible at a glance without clicking into anything.

Quick actions on the dashboard: The most common admin tasks are right there as big, clickable cards. No digging through menus for things you do every day.
Principle 07 — Nielsen Heuristic #7
Flexibility and Efficiency of Use
"Accelerators unseen by novice users may often speed up interaction for expert users."
⌘K / Ctrl+K shortcut: Press it from anywhere and the search bar gets focused instantly. Same muscle memory as Notion, Linear, or GitHub — power users feel right at home.

Full keyboard navigation: Tab through every sidebar item, hit Enter or Space to activate, Escape to close. The entire app works without touching a mouse.

Recurring schedules: Set it once — daily, weekly, monthly — and campaigns run automatically. Zero repeat effort.
Principle 08 — Nielsen Heuristic #8
Aesthetic and Minimalist Design
"Dialogues should not contain irrelevant or rarely needed information."
Clear typography hierarchy: Page titles are big and bold at 32px, subtitles are smaller and muted, card titles sit at 16px, labels are compact uppercase at 11px. Each size has one job to do.

Secondary text stays out of the way: Supporting info uses a lighter colour so it's readable but doesn't compete with primary content for attention.

Modals are ruthlessly minimal: A confirmation modal is just a title, one line of explanation, Cancel, and Confirm. That's it. No paragraphs, no extra options.
Micro-Interactions

Micro-interactions are tiny moments of feedback that tell the user "yes, the system heard you." They also make the interface feel more physical and alive.

Hover a stat card
Lifts up with a coloured glow shadow — feels like the card is reaching toward you
Hover a quick action
Icon grows slightly and tilts — a subtle hint that it's clickable
Hover a sidebar item
Full-width grey background lights up — you know exactly what's selected
Press a button
Slightly squishes inwards — tactile feedback like pressing a real button
Focus the search bar
Pill expands, border turns primary, subtle shadow drops — ready for input
Open a modal
Slides in and scales up with a springy bounce — feels natural, not mechanical
Toast notification
Slides in from the right and gently scales up — gets your attention without being jarring
Select an inbox item
Left border turns primary and background tints purple — clear which message is active

Accessibility

I made sure every interactive element works with a keyboard, makes sense to screen readers, and has enough colour contrast in both light and dark modes. The goal was full WCAG 2.1 Level AA compliance without sacrificing the look and feel.

Keyboard Navigation — WCAG 2.1.1

Every button, link, and interactive element can be used with just a keyboard. For custom div elements that act as buttons, I added explicit ARIA roles and keyboard event handlers so screen readers and keyboard users get the full experience.

/* HTML — Custom nav item with full keyboard support */ <div class="sidebar-item" role="button" tabindex="0" data-page="dashboard"> /* JS — Enter and Space key support */ item.addEventListener('keydown', e => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); item.click(); } });

Colour Never Used Alone
Status is always conveyed with both colour and text or an icon. For example, a badge says "Active" — it's not just green. Priority shows both a coloured dot and a label. This satisfies WCAG 1.4.1 Use of Colour so colourblind users aren't left guessing.
